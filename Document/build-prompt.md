あなたはフルスタックエンジニアです。`Document/project.md` の要件定義書に従って、VRPrintLab を実装してください。

## 前提
- 既存の試作 `index.html` に、Three.js によるプレビュー、Mat_Print/Mat_Base の扱い、ブラウザ内での .unitypackage(tar.gz) 生成ロジックがある。これをサーバー側（Next.js Route Handler）へ移植して再利用すること
- モデルは `models/Tshirt.glb`（プレビュー用）と `models/Tshirt.fbx`（同梱用）

## 進め方（フェーズごとに動作確認し、完了したら報告してから次へ進む）
1. Next.js(App Router, TS) + Supabase の雛形を作る。DBスキーマ（要件定義書 10章）をマイグレーションで作成し、RLS を設定する
2. 認証（メール / Google / Discord）、新規登録時のトークン付与
3. テンプレート一覧とエディタ（react-three-fiber。画像の貼り付け・拡大縮小・位置・回転・色・元に戻す/やり直す）。Tシャツをテンプレートの1件目として登録する
4. 作品の保存・再編集（Supabase Storage に元画像を保存する）
5. サーバー側での .unitypackage 生成（PC/Quest 用マテリアル、Prefab、README）と、トークン消費・購入済みの版の管理（params_hash で再DL無料を判定し、トランザクションで処理する）
6. ギミック付与（UdonSharp テンプレートスクリプトを同梱し、追加トークンを加算する）
7. Stripe によるトークン購入（Checkout + Webhook の署名検証、冪等性の担保、返金・チャージバック時の未使用分の取り消し、1か月あたりの購入上限）とトークンの有効期限（180日、古い順に消費）。決済の本番申し込みは、Phase 8 の規約類と本番公開のあとに行う
8. 導入ガイド、規約類のページ、管理画面
9. テスト（トークン計算・消費・失効・再DL判定の単体テスト、生成された unitypackage を Unity 2022.3 でインポートできるかの手動確認手順）

## 制約
- トークンの残高変更は必ずサーバー側で行い、クライアントからの値は信用しない
- 秘密鍵類は .env.local に置き、コミットしない
- フェーズごとに `main` からブランチを作成し（例: `feature/auth`）、作業の区切りでコミットする。コミットメッセージは日本語で簡潔に書き、`Co-Authored-By` などの帰属表記は入れない
- 不明点は勝手に決めず、要件定義書の「未決事項」に追記してから質問すること
