# Unity での読み込みの確認手順（手動）

サイトで生成した unitypackage が、Unity 2022.3 と VRChat SDK3（Worlds）で読み込めて、期待どおりに動くかを確かめる手順です。
パッケージの中身（ファイルの構成・GUID・マテリアルの書き換え・LICENSE など）は単体テスト（`npm test` の `tests/unit/package.test.ts`）で確かめているので、ここでは **Unity でしか分からないこと** を確かめます。

## いつ行うか

- パッケージの生成（`web/src/lib/package/`）か、Unity 用のスクリプト（`web/gimmicks/unity/`）を変えたとき
- テンプレートを追加・更新したとき（templates ブランチ）
- VRChat SDK・UdonSharp・Unity のバージョンを上げたとき
- 本番公開の前

## 準備

1. Unity 2022.3（VRChat が指定しているバージョン。この PC では 2022.3.22f1）
2. VCC か ALCOM で作った **Worlds** のプロジェクト。UdonSharp と ClientSim が入っているもの
3. 元のプロジェクトは触らず、**コピーに対して** 行う（Library フォルダごとコピーすると起動が速い）
4. 確かめるパッケージ
   - 実際の流れで確かめる: サイトで作品を作ってダウンロードする（ギミックなし・ギミックあり、見た目を変えた別の版も1つずつ）
   - ギミックをまとめて確かめる: `web/tools/verification/unity/make-test-package.mts` で全ギミック入りのテスト用パッケージを作る（手順は `web/tools/verification/README.md`）

## 確認すること

結果は下の記録表に書きます。「自動」の列に印がある項目は、`web/tools/verification/unity/` のスクリプトでログに結果を出せます（GUI の Unity での最終確認は手で行う）。

### A. 読み込み

| # | 操作 | 期待する結果 | 自動 |
|---|---|---|---|
| A1 | パッケージを Unity のウィンドウにドラッグ＆ドロップし、Import を押す | Console に赤いエラーが出ない | 〇（import.log） |
| A2 | 読み込みのあと、少し待つ | `Assets/VRPrintLab/<名前>/<名前>.prefab`（`<名前>` は `VRPrintLab_<テンプレートの slug>_<購入日時>`） が自動で作られる | 〇（VRPLBatchTest） |
| A3 | `Assets/VRPrintLab/<名前>/` を開く | `Template/`・`Tex_*.png`・`README.txt`・`LICENSE.txt`・`VRPrintLab.json` がある | |
| A4 | `Tex_*.png` を選んで Inspector を見る | Max Size が 2048、Android の設定も 2048 | |
| A5 | メニューの Tools > VRPrintLab > Prefab をすべて作り直す | エラーなく作り直される | 〇（VRPLBatchTest） |

### C. 上書きと共存

| # | 操作 | 期待する結果 | 自動 |
|---|---|---|---|
| C1 | 同じパッケージ（同じ版）をもう一度読み込む | 同じフォルダが上書きされ、ファイルやフォルダが増えない | |
| C2 | 同じ作品の、見た目を変えた別の版を読み込む | 別のフォルダになり、前の版の色・プリントは変わらない | |

### D. ギミック

| # | 操作 | 期待する結果 | 自動 |
|---|---|---|---|
| D1 | ギミック付きの Prefab を置き、再生ボタン（ClientSim）を押す | 選んだ動き（回転・ライト・パーティクル・持つ・振るなど）をする | 〇（VRPLPlayTest、GUI で実行） |
| D2 | Inspector でギミックの設定値（回る速さなど）を見る | サイトで設定した値になっている | 〇（VRPLBatchTest） |
| D3 | UdonSharp が入っていないプロジェクトで読み込む | コンパイルエラーにならず、Console に UdonSharp を入れるよう案内が出る | |
| D4 | VRChat の Build & Test で、クライアントを2つ起動する | 触る・持つなどの動きが、もう一方のクライアントにも同期される | |

### E. PC / Quest

| # | 操作 | 期待する結果 | 自動 |
|---|---|---|---|
| E1 | File > Build Settings で Android に切り替える | ピンク色（シェーダーのエラー）にならない | |
| E2 | VRChat SDK > Show Control Panel > Builder を開く | Prefab が原因のエラーが出ない（ポリゴン数の警告はテンプレートによって出る） | |
| E3 | Quest 実機（または Android の Build & Test）で見る | 表示・ギミックが PC と同じように動く | |

## 既知のこと（2026-11-03 時点）

- バッチモードと GUI では Unity の動きが違う（バッチモードで問題が出なくても GUI で固まった例がある）。最終確認は GUI で行う
- バッチモードで読み込んだ直後は UdonSharp のコンパイルが走らないことがある（組み立てスクリプトは組み立てのたびにコンパイルするので、Prefab は正しくできる）
- D4（全員への同期）と E3（Quest 実機）は、この PC に VRChat 本体がないため未確認
- ケーキ（6.7 万三角形）とスケートボード（1.06 万三角形）は、Quest の目安（1 つあたり 1 万）を超えている
