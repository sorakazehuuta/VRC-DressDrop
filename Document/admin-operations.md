# 運営の対応手順

管理画面は `/admin`。`profiles.is_admin` が true のアカウントだけが開ける（ほかの人には 404 になる）。
管理者にするには、Supabase の SQL Editor で次を実行する。

```sql
update public.profiles set is_admin = true where id = (select id from auth.users where email = '<メールアドレス>');
```

## トークンの問い合わせ

1. `/admin/users` でメールアドレスか表示名を検索し、ユーザーの詳細を開く
2. 「トークンの履歴」と「ダウンロード」で、問い合わせの内容を確認する
   - 二重消費: 同じ作品・同じ時刻にダウンロードの記録が 2 件あり、両方でトークンが減っているか
   - 不具合: ダウンロードの記録があるのに、パッケージが壊れていた・作られていなかったか
3. 「トークンの手動調整」で補填する
   - トークン数: 増やすなら正の数（有効期限 180 日のトークンを新しく付与する）
   - 理由: 必ず書く（例: 「二重消費の補填（問い合わせ #12）」）。履歴に操作した管理者と一緒に残る
   - 関係する ID: 補填の原因になった購入の ID（ダウンロードの表の右端）か支払いの ID
4. 誤って付与した分を戻すときは、負の数で調整する（有効期限が近いものから減らす。残高が足りなければ失敗する）

## お金の返金（不具合でダウンロードできなかった場合など）

1. Stripe のダッシュボードで、その支払いを返金する（全額または一部）
2. Webhook（`charge.refunded`）で、その支払いで付与したトークンのうち未使用の分が自動で取り消される
3. 使用済みの分は戻らない。不具合の影響を受けた分をトークンで補う場合は、上の手動調整を使う

## 購入した版の控えを消してほしいと言われた場合

利用者自身がダウンロード履歴の版の詳細から「この版の控えを削除」で消せる。消した版はダウンロード履歴から再ダウンロードできなくなる（購入の記録は残る）。
作品が残っていて内容が同じなら、エディタからは無料で作り直してダウンロードできる。

## 削除に失敗したファイル

`/admin` の「未完了のファイル削除」に一覧が出る。「未完了の削除を再試行」で再試行する。
本番では Vercel Cron が 1 日 1 回 `/api/cron/storage-deletions` を呼んで再試行する（環境変数 `CRON_SECRET` が必要）。10 回失敗したものは自動では再試行しないので、エラーを見て対応する。

## 作品・アカウントの停止

`/admin/users` で利用者を検索し、詳細画面から必要な範囲で止める。

- ダウンロード（購入した版）の「停止」: その版はダウンロード履歴から再ダウンロードできなくなる
- 作品の「公開停止」: 作品の編集・ダウンロードができなくなる
- 「アカウントを停止」: 購入・ダウンロードができなくなる

すでに VRChat に上げられたワールドや、BOOTH などでの販売は運営からは消せない。

停止・解除は、`admin_actions` に操作した管理者と一緒に記録される。

## お知らせの追加

`web/content/news.md` の `# お知らせ` のすぐ下に、新しい順になるよう追記して main にマージする。英語版の `web/content/en/news.md` にも、同じ日付で同じ内容を英語で追記する（英語版の見出しも `## 2026-11-07 Title` の形）。見出しは `## 2026-11-07 タイトル`（日付 + 空白 + タイトル）の形にする。形式が違う見出しはトップページに出ない。トップページには新しい3件が出る。

テンプレートを公開したときは、公開済みのものだけを書く（非公開のものは書かない）。

## テンプレート・ギミックのトークン数・公開状態・並び順・カテゴリ

`/admin/catalog` で変える。登録済みのものは、templates:sync / gimmicks:sync を実行しても上書きされない（ファイルの値は初回の登録だけに使う）。非公開のテンプレートは、管理者だけがエディタ（`/editor/<slug>`）で確認できる。

- 並び順: 行の左の ⋮⋮ をドラッグするか ▲▼ で入れ替え、「テンプレートを保存」「ギミックを保存」で反映する。テンプレートはこの順番が一覧の「おすすめ順」（最初に表示される順）、ギミックはエディタでの並びになる。新しく登録したものは最後に並ぶ
- カテゴリ（テンプレートだけ）: プルダウンで選び、「テンプレートを保存」で反映する。テンプレート一覧の絞り込みに使う。選べるのは `web/src/lib/templates/categories.ts` で決めたもの（新しいカテゴリを作るときはそこに足す）
- 読み（テンプレートだけ）: 名前のひらがな読み。一覧の「名前順」に使う（漢字の名前もあいうえお順に並ぶように）。新しいテンプレートを登録したら入れておく。空のときは名前の文字で並ぶ

## 登録の CAPTCHA と使い捨てメールアドレスの拒否

新規登録・ログイン・パスワード再設定に Cloudflare Turnstile の CAPTCHA を出す。トークンの検証は Supabase Auth が行う。使い捨てメールアドレスのドメインでの登録は、Supabase Auth の Before User Created フック（DB 関数 `hook_before_user_created`）で拒否する。Google / Discord での登録にも効く。

最初の設定（開発用）
1. SQL Editor で `web/supabase/migrations/20261114000000_disposable_email_hook.sql` を実行する
2. `web` フォルダで `npm run email-domains:sync` を実行し、ドメインの一覧（約 1 万件）を登録する
3. Supabase の Authentication > Hooks で「Before User Created」を追加し、Postgres の `public.hook_before_user_created` を選んで有効にする
4. CAPTCHA を試すときは、`web/.env.local` に `NEXT_PUBLIC_TURNSTILE_SITE_KEY=1x00000000000000000000AA`（テスト用のキー。必ず通る）を書き、Supabase の Authentication > Attack Protection で CAPTCHA を有効にして、Turnstile とテスト用のシークレットキー `1x0000000000000000000000000000000AA` を入れる。サイトキーとダッシュボードの設定は必ず一緒に変える（片方だけだとログインできなくなる）

本番の設定
- Cloudflare で Turnstile のウィジェットを作り（ホスト名は本番のドメイン）、サイトキーを Vercel の環境変数 `NEXT_PUBLIC_TURNSTILE_SITE_KEY` に、シークレットキーを Supabase の Attack Protection に入れる
- 本番のキーではテスト用のダミーのトークンが通らないため、`npm run test:db` と `tools/verification/e2e` は CAPTCHA をテスト用のキーにした Supabase でだけ実行する

運用
- 一覧はときどき（月に 1 回くらい）`npm run email-domains:sync` で更新する。一覧から消えたドメインは削除される
- 一覧にない使い捨てのドメインは、SQL Editor で `insert into public.disposable_email_domains (domain) values ('example-disposable.com');` のように足す（`source` が `manual` になり、同期で消えない）。サブドメインも拒否される
- 誤って拒否されたドメインは `delete from public.disposable_email_domains where domain = '...';` で消す（`list` のものは次の同期で戻るので、一覧の提供元にも報告する）
